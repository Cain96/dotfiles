# Unslop

文章から AI 生成のパターンを取り除き、人間の声を足す。

対象は**散文**。エージェントの返信そのものも対象に含む。コードの冗長性（不要なコメント、過剰な防御チェック、`any` キャスト、深いネスト）は `/deslop` の担当なので、ここでは扱わない。

## 手順

1. 下のパターンを走査する。
2. 書き直す。意味を保ち、意図した語調に合わせる。
3. 声を足す（次節）。
4. 自己監査する。「これが明らかに AI 生成だとわかる要因は何か」を自分に問い、残った兆候を潰す。

**書きながら直す。** 悪い文を書いてから掃除するパスは失敗することが測定されている。最初から悪い文を書かない。

## 声を足す

パターンを消すのは仕事の半分。無味乾燥で声のない文章も同じくらいバレる。

- **意見を持つ。** 事実を中立に並べるのではなく、それをどう見るかを書く。
- **リズムを変える。** 短い文で言い切る。そのあとに、条件や帰結まで抱えた長めの文を置く。混ぜる。
- **複雑さを認める。** 「すごい」より「すごいが、同時に少し不気味だ」。
- **一人称を使っていい。** 「私」は不作法ではない。
- **少し散らかしておく。** 完璧な構造は機械が書いたように見える。
- **具体的に書く。** 「懸念がある」ではなく「深夜3時にエージェントが延々と回り続けているのが落ち着かない」。

# パターン目録

## A. 内容

**A1. 大げさな飾り。** 「〜の礎となる」「〜を象徴する」「進化し続ける〜」「重要な転換点」「〜に大きな足跡を残した」「〜に深く根ざした」。飾りを消し、何が起きたかを書く。

**A2. 名前の羅列。** 媒体名・企業名・技術名を文脈なく並べる。1つに絞り、それが何を言ったかを書く。

**A3. 中身のない連用中止。** 「〜を実現し、」「〜を担保しつつ、」「〜することで、」「〜を可能にし、」。情報を足さず意義だけ匂わせる後置節。削るか、実際の根拠に展開する。英語の末尾 `-ing` 句（`highlighting...`, `ensuring...`, `fostering...`）と同じ現象。

**A4. 宣伝語。** 「洗練された」「シームレスな」「強力な」「先進的な」「圧倒的な」「革新的な」「必見の」。中立な記述に置き換える。

**A5. 曖昧な出典。** 「専門家によれば」「業界レポートでは」「一部では〜と指摘されています」。出典を名指すか、削る。

**A6. 定型の困難構文。** 「課題は残るものの、〜」「一方で、〜という側面もあります」「とはいえ、〜」。具体的な事実に置き換える。

## B. 語彙

**B1. AI 語彙。** 「また、」「さらに、」「重要な」「深掘りする」「強化する」「〜を浮き彫りにする」「〜における」「〜の観点から」「〜という文脈で」「多岐にわたる」「〜に他ならない」。平易な語に置き換える。

**B2. 「である」を飾る言い方。** 「〜という役割を果たします」「〜を有しています」「〜を備えています」「〜として機能します」「〜に位置づけられます」。全部「です」「あります」で済む。

**B3. 「単なる X ではなく Y」。** 「X にとどまらず Y」「X であると同時に Y でもある」。要点を直接言う。

**B4. 3つ組の強制。** アイデアを無理に3つに揃える。自然な個数で書く。

**B5. 同義語の巡回。** 一つの物を漢語・和語・カタカナで言い換え続ける（「利用者／ユーザー／使い手」「取得する／取ってくる／フェッチする」）。**日本語は英語より起きやすい。** 一つ選んで、繰り返す。

**B6. 偽の範囲。** 「〜から〜まで幅広く」。両端が同じ尺度に乗っていないなら、範囲ではない。項目を直接並べる。

## C. 体裁

**C1. 太字の乱用。** 固有名詞や略語を片端から太字にしない。

**C2. インラインヘッダー list。** 兆候は、**太字ラベルとコロンが直後の行を言い直している**こと。「**パフォーマンス:** パフォーマンスが向上しました」。これは散文に直す。ラベルが句点で終わり、項目を名指し、そのあとに本当に新しい情報が続く形（「**スキーマは TypeScript 側。** テーブル定義は1ファイルに集約されている。」）は兆候ではない。

**C3. 装飾絵文字。** 見出しや箇条書きから消す。

**C4. コロンの乱用。** 「つまり、」「すなわち、」「〜という点です。」の連発。箇条書きの前のコロンは問題ない。

## D. 対話の残骸

**D1. チャットボット常套句。** 「お役に立てば幸いです」「他にご不明な点がありましたら」「もちろんです！」「承知しました！」「〜ですね！」。消す。

**D2. 知識カットオフの言い訳。** 「詳細な情報は限られていますが」「最新の状況は異なる可能性がありますが」。調べるか、消す。

**D3. 追従的な語調。** 「素晴らしいご質問ですね」「おっしゃる通りです！」。直接答える。

## E. 埋め草

**E1. 埋め草表現。** 「〜するために」→「〜には」。「〜という点において」→「〜で」。「〜を行う」→「〜する」。「〜することが可能です」→「〜できます」。「重要なのは〜という点です」は丸ごと削る。

**E2. 過剰なヘッジ。** 「〜の可能性があると考えられます」「〜かもしれないと思われます」。**日本語は三重掛けになりやすい。** 一段に落とす。

**E3. 空虚な結論。** 「今後の展開が期待されます」「引き続き注視が必要です」。具体的な計画か事実を書くか、段落ごと消す。

## F. 借り物の抽象語

**F1. 抽象メタファー名詞。** カタカナで直輸入されているぶん、英語より検出しにくい。

| 使いがちな語 | 置き換え |
|---|---|
| 基盤 / サブストレート | 土台、下地、具体的な仕組みの名前 |
| 軸 / ベクトル | 方法、やり方 |
| レイヤー | 層。何の層かを言う |
| プリミティブ（名詞） | 部品、要素 |
| サーフェス（「API サーフェス」） | 公開されている関数、外から呼べる範囲 |
| ラチェット | その仕組みの実名、または「一方向にしか締まらない上限」 |
| フライホイール / 北極星 | やめる。実際の指標名を書く |
| ゴールドプレーティング | 必要以上に作り込むこと |
| エバキュエート（コードの移動） | 移す、出す |
| エンドゲーム | 最終段階 |

技術的に聞こえるが、たいてい平易で具体的な語がある。そちらを選ぶ。

## G. 素直な言葉

**G1. 感じではなく機構を書く。** これが目録全体で最も効く項目。

「データベースが手の届くところにある」「読める SQL」「スキーマに追従する型」は**感じ**を名指しているだけ。直すなら機構か数値にする。「`.toSQL()` はデータベースに送られる文字列をそのまま返す」「カラム名を変えるとビルドが落ちる」。

判定手順は2つ。

1. その文が読者に**何をするよう / 何を知るよう**言っているのかを問う。具体的な指示・事実・数値として言い直せないなら削る。
2. **その文が他プロジェクトのドキュメントにそのまま載るなら、このプロジェクトについて何も言っていない。** 削る。

**G2. 密な文は短くするか分ける。** 読者が読み返さないと構造が取れない文は、2つに割るか節を落とす。1文1アイデア。日本語は「〜し、〜であり、〜のため、〜となっています」と際限なく繋がるので、英語より意識して切る。

**G3. 能動態を選ぶ。** 「〜されます」「〜が行われます」「〜となっています」を捕まえて、動作主を名指す。「クエリが検証されます」→「コンパイラがクエリを検証します」。「ファイルが読み込まれます」→「ローダーがファイルを読みます」。敬体と結びつくと自然に見えてしまうので、英語より温存されやすい。動作主が不明か本当にどうでもいい場合だけ受身でよい。

**G4. 副詞を削るか、強い動詞にする。** 「高速に動作します」→「速いです」か実測値。「大幅に改善します」→計測した差分。弱い動詞を副詞で支えているなら、動詞が間違っている。

**G5. 平易な語を選ぶ。** 「実施する」→「する」。「活用する」→「使う」。「有する」→「ある」。「可能である」→「できる」。「必要となります」→「要ります」。「〜を実現する」→「〜する」。凝った類語が明確だったことはほとんどない。

## 英語で書くとき

日本語には対応する現象がないため上の目録から外してあるが、英語の文章を書くときは追加で適用する。

- **em dash（`—`）は全面禁止。** 句点かカンマで書く。括弧に逃げるのも別の兆候に置き換えるだけなので不可。思考を分けたいなら文を切る。
- **見出しは sentence case。** title case にしない。
- **カーリークォート（`“ ”`）を使わない。** 直線クォート（`" "`）にする。
- `utilize`→`use`、`leverage`→`use`、`facilitate`→`help`、`numerous`→`many`、`in the event that`→`if`。
- AI 語彙: `Additionally`, `crucial`, `delve`, `enhance`, `fostering`, `garner`, `interplay`, `intricate`, `landscape`, `pivotal`, `showcase`, `tapestry`, `testament`, `underscore`, `vibrant`。
- `serves as` / `stands as` / `boasts` / `features` → `is` か `has`。

## 関連

- コードの冗長性（不要なコメント、過剰な防御チェック、`any` キャスト、深いネスト）は `/deslop` の担当。リポジトリによっては `.claude/commands/deslop.md` として存在する。対象が違うので競合せず、併用する。無いリポジトリではこの skill はコードに手を出さない。
- コメントは `comment-sicko`（`subagent_type: "comment-sicko"`）がより厳しく扱う。ここでの規約はコメントにも適用されるが、削除の判断は comment-sicko のほうが強い。
